# Dot → Harness 插件

这是安装到 DeepSeek Harness 的原生插件，包名为 `dot-dsh-management`，维护者为奥克斯木木山。通过它，Dot 可以读取本人已保存的项目与会话，并给 Harness 派任务、查进度、补充要求和取消任务。任务沿用 Harness 的当前模型、工具与审批，可以修改项目文件、运行命令。

## 安装和连接

在 Harness 新建「创造模式」会话，把正式发行页提供的一句话安装指令交给它。指令包含该版本的公开 `.tgz` 地址，Harness 通过官方插件管理工具下载并安装；需要时由本人确认安装审批。

安装完成后打开侧栏「Dot 连接」，点击「连接我的 Dot」。插件自动准备本机与账号侧配置；需要时在官方页面登录自己的账号并确认授权，最后验证读取和派任务。已有连接和任务会保留。

只安装这一个原生包。它已包含本机读取、管理与 MCP 服务源码；不需要再安装 `dot-dsh-connector` 作为另一个 Harness 插件。包中不包含用户凭据、账号连接或任务记录。

正式源码与版本下载见 https://github.com/oxmumu3/dot-dsh-connector 。

首次打开，点击「连接我的 Dot」。插件准备本机服务，并在 ego lite 中打开专属连接页面，自动填写可配置项目；你在官方页面登录自己的 OpenAI / ChatGPT 账号，确认目标 workspace 和授权。完成后，插件自动核实云端通道、项目读取和一个只回复验证标记的原生任务。无须复制密钥、通道编号或终端命令。

准备、登录与授权、验证的进展都在本页显示；可以打开原窗口、暂停后继续。没有完成真实读取与原生任务时，不会显示验证成功。平台页面变化、账号权限不足或组件下载失败会保留明确的重试提示。旧外部部署继续使用原配置，不触发替换。

当前支持 macOS、标准 Applications 路径下的 Harness `0.2.1-rc.2`、Harness 自带的 Node 与 Python 运行时，以及 ego lite 连接窗口。本机缺少 Ego 时，点击「安装 Ego 并继续」会下载官方安装包、校验签名并安装；你完成 Ego 首次设置后回到插件继续，不要求导入其他浏览器的数据。插件读取 `DSH_HOME`，缺省使用本人 `~/.dsh`。模型、微信与平台凭据不会被复制。

## 日常使用

- 在「总览」查看本机状态；在「访问记录」查看连接调用的时间、工具和结果；在「任务」查看连接创建的任务。
- 按项目编号、请求编号、状态或归档范围筛选；文字搜索限当前页。任务详情显示项目、原生会话、最近活动、结果及需要回答的问题。
- 打开原生会话处理审批和回答。任务结束后可继续；运行中可选择排队追加或补充当前要求，任务身份无法确认时先核对原会话。
- 归档保留记录和重复请求识别，不删除项目文件。累计超过 100 项已结束任务仍可使用；同时未结束任务最多 100 项，账本总大小仍受 16 MiB 保护上限约束。
- 暂停接入阻止新的内容读取和派活，状态、任务查询、归档和取消仍可使用。正在执行的任务继续运行，取消不会撤销已完成的文件修改或命令。
- 页面每 10 秒刷新一次可见内容并避免请求重叠；局部读取失败保留最后成功数据并标记时间，过期任务详情禁止操作。

云端状态自动读取已登记官方 Tunnel 的实时健康信息，区分通道在线、离线和待核实，另列最近云端交互时间。空闲与暂停接入不等于断线；通道健康不等于 Dot 账号授权或任务成功。检测配置见源码仓库 `docs/setup-lifecycle.md`。

记录从连接管理启用后开始，不能补回此前完整历史，也不等于两端聊天同步。现有通道不能可靠区分每次调用来自 Dot 还是 Codex，页面不会虚构两种已验证身份。

Harness Desktop 需保持运行，管理页可以关闭。插件只启停自己取得的服务资源，停用和更新保留数据，已交给 Harness 的任务不会因此自动取消。明确启动成功后可在下次加载恢复本机服务，明确停止会取消恢复意图。新的插件托管安装自动分配空闲本机端口，重载时可重新分配；显式固定端口被占用或存在未知运行锁时会停止启动，须先核对原实例。

## 旧版外部服务兼容

已有 `enabled:true,tokenFile` 配置继续使用原管理网关，不迁移、覆盖或关闭外部服务。更新同一个 `dot-dsh-management` 插件，保留该配置与账号连接：

```yaml
- id: dot-dsh-management
  name: dot-dsh-management
  disabled: false
  config:
    enabled: true
    tokenFile: /absolute/private/path/admin-token.key
```

只提供本人私有 token 文件的规范路径引用，不把值写进 YAML、聊天或前端。Host 校验本机 owner，并只向固定 loopback 管理端点发起请求；worker 使用独立通道和短期单次 capability。

外部兼容模式保留管理端口 31473、worker 端口 31474；新 managed 模式由 Host 向 worker 提供本实例自动分配的地址。一个已加载的插件只服务当前选定的管理器。明确切换模式时先确认旧通道没有活动任务；即使旧服务进程保留，旧、新两个任务通道也不会被这个 worker 同时处理。详见源码仓库 `docs/setup-lifecycle.md`。

旧后台服务会进入明确的兼容模式：保留原有状态、任务列表、查询、取消和 worker 通路，隐藏它不支持的新版筛选、归档及页面接续。更新后台服务后才启用这些增强；不会通过失败重试猜测权限，也不会在升级插件时擅自重启外部服务。

## 构建与验证

在源码根目录运行 `npm run build:plugin`，然后 `npm pack ./management-plugin --pack-destination ./dist`。构建生成原生客户端、内嵌服务源码及许可证，前端使用 Harness 自带 React、Zod 和页面插槽。依赖由正常插件安装流程安装。

`0.6.0-preview.13` 增加异常退出恢复、7 天到期提醒和自助更新连接授权。提醒日期来自创建表单的 30 天期限，仅为预计到期；旧记录缺少日期时明确显示待确认。更新时先验证新授权，成功后替换旧授权，保留通道、个人插件和任务。窗口丢失或误关密钥弹窗时有对应恢复入口。

源码测试、归档安装、原生加载和真实 Dot 调用需要分别验收。实际机器状态与已验证边界见源码仓库 `docs/verification.md`。是否能安全热更新由宿主决定，不能为试验而重启正在工作的 Host。
