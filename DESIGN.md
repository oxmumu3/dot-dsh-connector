# Dot → Harness workspace

Product direction: precise task orchestration, not a family-assistant visual clone. The user reference demonstrates implementation quality only; never inherit its palette, subject matter or serif typography. The plugin owns its workspace, not the host sidebar.

- Canvas #f7f8fa / white, graphite ink #20242c, muted #687181, restrained solid signal-blue #3268d6 for one primary action; semantic running/waiting/error colors remain distinct. Dark mode uses graphite surfaces with readable hierarchy. No blue-purple gradients.
- System sans typography, strong legible task titles, quiet compact metadata; use proportional space and disciplined type rather than marketing-sized headings. Controls at least40px; dense task rows remain readable.
- A deliberate grid, fine separators, restrained corners and whitespace support real work. Avoid three oversized metrics, nested card walls, glow, emoji, decorative pseudo-charts and a fake host sidebar.
- First-use is the main feature: one “连接我的 Dot” action, clear3-step progression and explicit human login/grant waits. Automatically configure everything supported; no manual key or shell instructions on the primary path.
- Connected: active work, waiting questions, recent outcomes and next action first; fresh health and historical timestamps are separate. Diagnostics/paths/ports live in expandable details.
- Preserve real task filters, details, native-session navigation, continuation, archive, pause and original data. No fake task composer when the backend has no native-start RPC.
- Keyboard focus, clear button states, textual status, reduced motion and390px layout are delivery requirements.
