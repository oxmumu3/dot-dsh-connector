# Public SDK compatibility gate

`compatibility.yml` runs on pushes, pull requests, manual requests and 03:00/15:00 UTC daily. `npm-release.yml` calls the same workflow before validation and confirms the compatibility source SHA matches the dispatched source. The publish job retains its existing artifact/run/source digest checks and its isolated OIDC permission; tests and checkouts receive no OIDC.

Discovery reads official npm metadata and validates `compatibility.json`, exact engine/runtime declarations and lock files. Its `verifiedSdks` list drives the Linux matrix. The recorded unsupported alpha remains excluded. New releases or failed discovery block the gate; the workflow never widens support automatically. The existing live `npm run check` runs again immediately before packing.

The Linux matrix installs exact public SDK packages without lifecycle hooks, then runs the 13-file contracts with synthetic HOME, workspace, state and tokens. The current suite contains 162 tests per SDK, 810 across the five admitted SDKs; release counts are recorded in [the verification ledger](verification.md). CI pins Node24.22.1 and npm11.15.0; the probes require Python3.10+. The Linux runner requires passwordless `sudo`, `unshare`, `ip` and `setpriv`: fixed system tools create a network namespace and enable loopback, then drop to the original runner UID before repository code executes. A real loopback roundtrip and denied non-loopback, custom-DNS and non-Node-child connections must be observed; missing sandbox support, skipped tests or incomplete results fail closed.

A separate `macos-26-intel` job runs every SDK in `verifiedSdks` serially, with a separate exact official Host carrier, pnpm11.28.5 and fresh synthetic web profile for each. It packs the management subpackage, installs it through the official CLI and checks enable, disable/re-enable, a new-process restart, official CLI uninstall and post-uninstall state. Actual installed protocol/Cordis ABI, every installed archive file, owner Remote, external denial and the pinned protocol error path must pass for all five SDKs; `verify-host-matrix.mjs` then requires the complete SDK set and a common archive fingerprint. Public package acquisition can access npm; each actual Host runs under the original loopback-only `sandbox-exec` policy. It does not load an installed Desktop app or private profile. Desktop setup remains blocked in this web fixture, with services stopped and account unverified; this does not prove onboarding, cloud authorization, real tasks, model output or Dot/phone receipt.

CI-only helpers live under `scripts/ci/`. Local runs may use `discover --official FILE` with a recorded discovery fixture and existing public carriers. The workflow always uses live discovery and fresh public dependency installation. Offline Host/cache flags exist only for local public-package fixtures; hosted jobs do not link user caches. Proofs and bounded TAP logs are retained as Actions artifacts for seven days. Linux namespace behavior and the hosted Actions run must be observed on the actual runner before calling the remote gate accepted.

The workflow preserves these artifact layouts:

- `compatibility-discovery-<run_id>-<attempt>/`: the exact live discovery snapshot for that run and attempt.
- `compatibility-contracts-<sdk>/`: per-SDK contract counts, bounded TAP logs and actual network proofs.
- `compatibility-official-hosts/`: `matrix-proof.json` plus one `<sdk>/` directory per admitted SDK, containing lifecycle/ABI, network and installed-byte proofs, bounded install/Host/uninstall logs and the tested archive under `assets/`.
- `npm-release/`: the validated native archive and `release-manifest.json`, bound to the publication source, run, attempt and SHA-256; the OIDC job publishes these exact bytes.

macOS explicitly allows the bind operation needed by its ephemeral CI services, while inbound/outbound rules remain loopback-scoped. The bind predicate alone is not treated as proof of a specific listening address: the actual Host proof inspects its Node TCP servers and requires loopback listeners. Network probes independently verify custom DNS lookup and a non-Node subprocess cannot connect externally. Linux descendants run with `no-new-privs` after the runner UID/GID is restored.
