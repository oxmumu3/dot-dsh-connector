# 连接自己的 Dot

先按[一句话安装](install-and-connect.md)在 Harness 的「创造模式」安装并启用插件，再打开侧栏「Dot 连接」，点击「连接我的 Dot」。

想先看完整过程，可打开 [首次连接的 HTML 模拟](first-connection-demo/index.html)。界面的三栏是阶段：按两个站点都需要登录计算，实际为六个人工环节（开始、登录 OpenAI、选择工作区并创建通道、确认运行密钥、登录 ChatGPT、确认创建个人插件），之后自动验证。已登录时会跳过相应登录；验证码、额外连接授权或工具审批可能增加操作。若本机还没有 Ego，连接前还会提示安装并完成首次浏览器设置。环节数不是点击次数，具体拆解见 [计数与源码核对](first-connection-demo/README.md)。

`0.6.0-preview.12` 使用 ego lite。若本机缺少 Ego，插件提供「安装 Ego 并继续」：自动下载官方安装包、校验签名并安装，你只需完成 Ego 首次设置后继续，无须导入其他浏览器的数据。插件会准备本机服务、下载官方 Tunnel 组件，并在同一个 ego 工作空间接续官方页面。可使用 ego 已有的有效登录；不会读取日常 Chrome、导出 cookie 或复制其他应用的登录凭据。你只需在官方页面登录自己的账号，确认目标组织 / ChatGPT workspace 和最终授权；其余支持自动填写的内容由插件处理。无需把密钥、通道 ID 或命令复制到聊天中。

连接后，插件会让实际 Dot 列出项目，并派一个只回复验证标记的小任务。只有云端新鲜健康信息、真实项目读取记录和相同请求编号的原生任务完成回执齐全，才显示「连接验证已完成」。自检指令要求只回复验证标记，不读写项目文件、不执行命令；执行仍沿用 Harness 的上下文和审批设置。

## 当前登录验收范围

`0.6.0-preview.12` 已通过 Harness 官方界面安装并启用，54 个安装文件与源码及归档完全一致。使用安装目录中的 provider 和实际 worker，经真实 Dot 完成一次新鲜项目读取及恰好一个原生验证任务；独立回读确认首轮成功结束、非缓存、请求与结果精确匹配，管理页自动从等待首次调用变为云端在线。

2026-10-23，当时安装的 `0.6.0-preview.9` 在本人已有有效登录的 ego 中，完成了一条新连接的实际验收：新建通道、创建专用运行密钥、创建并授权个人插件；密钥由插件自动保存到本机，仅当前用户可读写（文件权限 `0600`），无需复制。随后，真实 Dot 通过这个新插件成功列出项目，派发一个原生验证任务并取得精确匹配的完成结果。管理页自动显示「云端通道在线」和「连接验证已完成」。

随后通过 ChatGPT 官方「添加账户」→「使用 Google 继续」→「使用其他账号」，到达 Google 邮箱输入页。本人完成登录后，实时回读已登录的 ChatGPT 页面。此前独立 Chromium 的“不安全浏览器”拒绝没有在这次 Ego 交互登录中出现。此证据覆盖实际 Google 登录，不是清空浏览器资料、创建全新 Google / OpenAI 账号或所有账号资格的验证。

登录、验证码和授权由官方页面决定。若账号仍被拒绝，保留当前 ego 页面并显示具体等待原因；不会换浏览器、伪装浏览器或复制登录凭据绕过。未安装 Ego 的机器会增加一次安装确认和浏览器首次设置。安装模块回归 31/31 通过，正式安装代码已在隔离目标中真实完成官方缓存安装包校验、复制、签名与系统安全检查；仅最后打开应用被拦截，现有 Ego 未改动。GUI 首次设置与完全空白机器仍未验收。

连接页面交给你操作后，完成官方确认，再回到 Harness 点击「继续连接」。它会沿用同一个 ego 工作空间，核对实际结果后继续，不要求搬运密钥或编号。创建运行密钥后，请保留「Save your key／保存密钥」窗口，再回到 Harness 点「继续连接」；插件保存成功后才能关闭该窗口。如果提前点 Done 隐藏密钥，preview.13 提供「重新创建授权」恢复入口；旧密钥和连接保留，重新创建后仍由插件保存，无需复制。

## 日常派任务

在自己的 Dot 里说：

> 请列出 Harness 已登记的项目，让我选择一个；在所选项目中新建任务，阅读项目说明并列出三项下一步建议，不修改文件。完成后返回任务编号和结果。

之后可以要求它修改项目、运行验证、补充当前任务、查进度或取消。模型、工具和审批沿用 Harness；需要回答或批准时，在「任务」里打开对应原生会话。Harness 需保持运行。

## 中断后继续

preview.13 对已确认死亡的自有进程增加自动锁恢复，并通过父子进程生命线关闭该实例启动的 Tunnel 子进程。下一次打开可恢复已启用的连接；不接管活跃或归属不明的服务，也不重放写任务。正式安装后的实测状态以验收记录为准。

关闭登录窗口、网络暂时不可用或平台表单变化时，回「Dot 连接」查看当前提示。选择「继续连接」或「打开连接窗口」，会沿用本次安装的私有资料和已建立资源。暂停仅关闭插件自己启动的连接进程，保留账号连接与任务记录。

成功配置且未暂停连接时，插件再次启动会恢复原通道，不重复派发自检任务。显示「通道已启动 · 等待首次调用」时，可以直接向 Dot 派任务，无需重新登录或点击「重新验证连接」。首次真实调用后，界面会自动核实并更新云端状态；上次完整验证时间仍单独保留，不会当成这次新完成的验证。若接入已暂停，先点击「恢复接入」；若状态读取失败，按页面提示刷新核实。

`0.6.0-preview.11` 已完成本机插件冷启动恢复实测：等待首次调用期间通道持续保留，真实云端项目读取成功后，管理页自动转为「云端通道在线」和「连接已恢复」。这次恢复没有重新登录、重新验证或派发新的验证任务，浏览器连接保持已完成状态。本次覆盖插件冷启动恢复，未测试整机重启。

preview.13 增加自助更新连接授权：运行密钥按 30 天期限创建，剩余 7 天时提示。日期来自创建时的本地观察，标为预计到期；旧密钥没有日期时显示待确认。点「更新连接授权」，在官方页面完成必要登录与最终创建确认，插件自动保存并验证新授权，验证成功才替换旧授权。全程复用原通道、个人插件与任务；失败仍保留旧授权，可以按提示继续。若原 Ego 工作空间已删除，点击「重新打开连接窗口」恢复。

已有外部管理服务会继续使用原通道；插件不会自动迁移或替换。高级路径、端口和本机维护操作保留在「连接设置」的诊断区。旧版五步手动配置见 [手动连接参考](new-user-connect.md)。

## 当前支持范围

macOS、标准 Applications 路径下的 Harness Desktop `0.2.1-rc.2`、Harness 自带的 Node 与 Python 运行时。首次连接使用 ego lite，并下载 OpenAI Tunnel 组件；网络失败可以重试，不调整系统代理或停用现有网络。首次登录、验证码、平台最终授权以及组织管理员限制仍由官方页面控制。安装插件不会赋予账号本来没有的组织 / workspace 权限。
