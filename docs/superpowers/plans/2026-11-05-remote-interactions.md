# Remote interaction implementation plan

Goal: implement the approved remote-question/single-approval design, retaining official Harness UX and exact task ownership.

1. **Native SDK adapter.** Change `management-plugin/src/native-worker.js`, `client.js` and their tests. Add optional official `uiSession` injection; absence disables interaction answering without breaking existing task control. Read actual pending carriers, associate tool calls with exact owned turns, expose bounded descriptors and execute `answer_question`/`decide_approval` with structured validation. Include official question-reply events for timed continuations. First add worker tests for success, stale/foreign/manual requests, missing call IDs, option errors and no prompt substitution; observe RED, then implement.
2. **Durable broker.** Change `src/native-tasks.js` and focused tests. Extend report/job/command schemas with defaults so old version-2 state remains readable. Add two control methods, durable idempotent operation receipts, priority dispatch, single consumption, fail-closed restart/lease behavior and exact question-reply continuation. First add tests that exercise the public `createNativeTasks` protocol and genuine persisted state, observe RED, then implement. Keep transport authority in existing claim/lease capabilities.
3. **MCP and management.** Change `src/mcp.js`, `bridge.js`, `management.js`, relevant onboarding tool rosters and native client display. Register both strict effectful tools with explicit per-request-user-decision instructions; enforce pause policy and audit IDs/outcomes without answer content. Add MCP in-memory transport tests that inspect actual listed schemas and call the real manager/broker. Update visible waiting text so it explains that Dot can answer supported requests; unsupported/foreign requests still offer the ordinary Harness path.
4. **Independent integration.** Run root/worker/broker tests plus a real exact-SDK carrier integration for an owned blocking question, timed continuation and native approval. Observe applied receipts and terminal events, not just accepted/idle. Check that desktop answering invalidates the remote request and unrelated manual work continues.
5. **Delivery.** Bump to preview.25 only after implementation contracts stabilize. Update compatibility suite coverage and package/source manifests, without dropping previous coverage. Verify exact current official metadata, all five SDKs, native Host lifecycle, then use the established Trusted publisher. Verify npm latest by an actual fresh official CLI installation, public owner/assets hashes and current market entry. Reuse the existing authorized Ego task space for real Dot acceptance; document exact remaining external blocks instead of claiming a mock or connection badge is end-to-end success.

Baseline: canonical public main `b88ec3f`, existing native tasks/worker/MCP integration tests 71/71 passed with Node 24.22.1 before edits. The approved design itself supplies the task boundaries; no extra design approval is required.
